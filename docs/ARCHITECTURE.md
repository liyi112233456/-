# 系统架构

```text
浏览器 SPA
  ├─ IFC 上传、自动/Excel 顺序选择与参数配置
  ├─ SSE 实时任务状态
  ├─ 自包含 Canvas 三维线框渲染器
  ├─ 六自由度安装动画 / 步进 / 碰撞结果 / 机器人路径叠加
  └─ 结果与控制器程序下载
           │ HTTP / SSE
FastAPI API 服务
  ├─ SQLite 任务状态
  ├─ 文件与结果权限边界
  ├─ GZip 大型 JSON 传输
  └─ 独立计算进程启动器
           │ subprocess
计算 Worker
  ├─ IFC STEP 索引
  ├─ BREP / ExtrudedSolid 轴线恢复
  ├─ X/Y/Z 正反方向空间拓扑与任意方向循环核心求解
  ├─ Excel/CSV/TSV 人工安装顺序映射与完整性校验
  ├─ 已安装钢筋动态障碍世界
  ├─ 刚体钢筋 SE(3) 直线 / 旋转折线 / RRT 曲线路径搜索
  ├─ 三维胶囊体碰撞检查与碰撞报告
  ├─ 浏览器模型与 CSV/JSON 输出
  ├─ 由碰撞通过的六自由度钢筋路径生成 TCP 位姿与五次多项式时间参数化
  └─ ABB RAPID / KUKA KRL / URScript
```

## 数据持久化

每个任务位于 `data/jobs/<task_id>/`，包括输入 IFC、输出、日志和结果 ZIP。SQLite 仅保存轻量状态和摘要，不保存大型几何。

## 计算隔离

API 不在请求线程中执行 IFC 解析。每个任务由独立子进程处理，因此大型模型失败或占用 CPU 时不会阻塞前端接口。生产环境可把启动器替换为 Celery/RQ/Kubernetes Job，而无需修改前端 API。

## 规划证明边界

自动拓扑采用“钢筋轴线胶囊体 + 多方向扫掠阻挡图”，安装顺序由拆卸拓扑反转得到；循环核心中的强制消解只提供第二步路径搜索的候选顺序，不宣称实际路径可行。Excel 顺序不做拓扑可行性背书。

第二步在 SE(3) 中把钢筋作为刚体，姿态由三维抓取点位置和 `xyzw` 四元数表示；对每条控制边按平移和旋转步长插值，对此前已安装的钢筋轴线胶囊体做精确三维线段距离检查。目标位已有设计接触可保留，中途新增穿透会失败。该检查不含机器人完整连杆、夹具、模板、混凝土和现场其他障碍物，仍需全实体数字孪生复核。
